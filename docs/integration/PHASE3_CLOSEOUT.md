# Phase 3 closeout — Orin Q2_0 tested scope — 2026-10-13

Phase 3 is complete for the validated Orin AGX Q2_0 native-serving route and
the allocation/transfer classes listed below. This is not a general memory
capacity curve, cold-storage comparison, or graph-pool size claim. Model and
pack artifacts remain under ~/models/strata-orin-validation/.

| Plan gate | Evidence and outcome |
| --- | --- |
| Unique allocation ownership and future reservations | Owner traces cover the cache, VMM ranges/chunks, SessionState, prefill, verifier, MTP and pageable/pinned staging owners. Reservation events are kept separate from allocated bytes. Orin VMM shrink/regrow preserved slot data and balanced 41 events. The independent Q2_0 PLE and selected owner/graph CTests passed. See the [owner/64K screen](../../bench/results/2026-10-12-phase3-q2-owner-64k/README.md), [auto-reservation reconciliation](../../bench/results/2026-10-12-phase3-q2-auto-reservation/README.md), and [fresh PLE rerun](../../bench/results/2026-10-13-phase3-q2-ple-user-rerun/README.md). |
| Late-workspace and cgroup pressure | Cache/context and prefill-chunk/workspace screens recorded requested reservations, actual cache slots and owner peaks. Pressure-aborted attempts were retained and not treated as admitted runs. Accepted campaigns used the six-GiB host/effective floor and separate 3-GiB workspace reserve. Cancellation at 8K, 16K and 32K prompt lengths recovered on the same service; floor aborts had no OOM kills. These are tested cells, not a universal RAM boundary. See the [cache/context state screen](../../bench/results/2026-10-12-phase3-q2-cache-context-state/README.md), [32K 18-GiB abort](../../bench/results/2026-10-12-phase3-q2-actual32k-context64k-18G/README.md), [32K 19-GiB pass](../../bench/results/2026-10-12-phase3-q2-actual32k-context64k-19G/README.md), and [32K cancellation recovery](../../bench/results/2026-10-13-phase3-q2-cancel-32k/README.md). |
| Failed registration, pageable fallback and VMM resizing | Injected host-registration failures fell back to pageable copies; the segmented VMM lifecycle test verified resize and data preservation. These tests qualify the fallback/lifetime contract, not a claim that pinning is beneficial. See the [pinned fallback pressure test](../../bench/results/2026-10-09-pinned-fallback-pressure/README.md) and [VMM address-range test](../../bench/results/2026-10-10-phase3-vmm-va-reservation/README.md). |
| Transfer choices and end-to-end effect | Pageable/pinned staging and mapped/pread tests include owner bytes, faults, disk counters where available, request latency, token output and persistent state. Held-out 16K and 32K mapped/pread tests found no reliable general request win; pread reduced major faults but two 32K pair reversals made the paired interval wide. The held-out 16K fill/staging comparison found staging 0.40% slower. No transfer default changed. Whole-device reads include unrelated I/O and page cache was not cold. See the [16K mapped/pread result](../../bench/results/2026-10-13-phase3-q2-mapped-pread-16k-heldout/README.md), [32K mapped/pread result](../../bench/results/2026-10-13-phase3-q2-mapped-pread-32k-heldout/README.md), [16K prefetch staging result](../../bench/results/2026-10-13-phase3-q2-prefetch-stage-16k-heldout/README.md), and [pinned-stage confirmation](../../bench/results/2026-10-13-phase3-q2-stage-pin-16k-heldout/README.md). |
| CUDA Graph and physical-owner observations | Fine NVMap traces covered captured Q2_0 requests at 8,232 and 65,536 context, spec2/3/4 and a fixed cache. They retained sample cadence, event-aligned owner deltas and cgroup/host headroom. Spec1 and graph-disabled controls are unsupported by the native route and were refused before a request. NVMap owner changes are brackets, not isolated executable or graph-pool bytes; private driver allocations remain unpriced. See the [8,232-context trace](../../bench/results/2026-10-13-phase3-q2-graph-fine-nvmap/README.md), [64K spec2 trace](../../bench/results/2026-10-13-phase3-q2-graph-fine-nvmap-context64k/README.md), [spec3 trace](../../bench/results/2026-10-13-phase3-q2-graph-fine-nvmap-context64k-spec3/README.md), [spec4 trace](../../bench/results/2026-10-13-phase3-q2-graph-fine-nvmap-context64k-spec4/README.md), and [spec1 refusal](../../bench/results/2026-10-13-phase3-q2-graph-fine-nvmap-context64k-spec1/README.md). |
| Regression and independent oracle | The Q2_0 artifact-aware PLE check passed all seven stages for three tokens (worst relative L1 1.148e-7), the selected memory/owner/PLE CTests passed 15/15, and integration Python discovery passed 124/124. A fresh supervised refresh on 2026-10-13 repeated all three passes; see the [refresh report](../../bench/results/2026-10-13-phase3-q2-ple-final-refresh/README.md). These tests validate the scoped contracts, not model quality across other artifacts. |

All admitted runs in this scope stayed above the six-GiB guard; no OOM kill or
invalid state/output parity was observed. The status is complete for these
tested route/model combinations with the explicit unsupported exclusions above.
No NInfer execution component or experimental transfer setting is promoted.
Reopen Phase 3 if later work changes allocation lifetime, adds a graph-disable
route, promotes a transfer mode, or brings a new model/backend into scope.
