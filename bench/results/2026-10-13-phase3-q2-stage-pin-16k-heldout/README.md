# Q2_0 16K pageable versus pinned staging: held-out confirmation — Orin — 2026-10-13

This confirmation followed the [three-pair primary-prompt screen](../2026-10-13-phase3-q2-stage-pin-16k/README.md), which showed a small pinned-stage advantage. To test that signal on a new exact-length prompt, the staging harness gained a `heldout_blue` prompt variant; its existing `primary` variant remains byte-for-byte unchanged. The held-out prompt is 16,384 formatted tokens, with tokenizer file hashes and the exact token-ID sequence retained in `prompt.json`. The model is Qwen3.8-Flash-Next-GSQ-RCO Q2_0 Orin-validation, loaded from `Qwen3.8-Flash-Next-GSQ-RCO-Q2_0-00001-of-00002.gguf` and `Qwen3.8-Flash-Next-GSQ-RCO-Q2_0-00002-of-00002.gguf`, with the local Q2 PLE pack and `q2-expert-profile.bin`; all model files stayed under `~/models/strata-orin-validation/`.

A separate randomized traced pair checked correctness and ownership on the held-out prompt. Pageable and pinned arms matched all eight output IDs and all nine persistent-state fields. Each arm recorded 304 allocations and 303 frees, with only the resident weight arena remaining requested-live. Both stage owners requested 353,894,400 bytes (337.5 MiB); each had 256 stage-buffer allocation and free events.

The timing confirmation then ran seven independent fresh-process pairs with tracing disabled. Each arm used the same Q2_0 model, exact prompt, eight-token continuation, 3,000 expert slots, FP16 KV, `prefill 512`, CLI `spec 2`, 16,424 context reservation and six-slot prompt cache. The harness randomized arm order with seed 870128. All seven pairs emitted matching token IDs.

Pinned-minus-pageable paired request-time delta was −0.23%, with a seven-pair bootstrap 95% interval from −2.47% to +0.72%. The interval includes no change and the median effect is below the project's 5% improvement threshold. Prompt-time delta was −0.24% (−2.55% to +0.65%); decode-time delta was +1.18% (−1.31% to +3.70%). Median engine request time (`prompt_ms + decode_ms`) was 102.873 seconds pageable and 103.094 seconds pinned. The descriptive inclusive p95 estimates were 133.156 and 124.257 seconds, respectively, with only seven samples per mode. One pair had a large pageable outlier, which is retained in the paired samples. Focused stage-buffer tests passed 11/11 and full integration Python discovery passed 122/122 after adding the prompt variant. The held-out confirmation does not reproduce a reliable pinned-stage benefit, so pageable staging remains the default.

The 28-GiB cgroup supervisor passed with minimum host availability of 17.505 GiB and minimum effective cgroup headroom of 7.477 GiB. The cgroup recorded no OOM events or OOM kills. System-wide swap use peaked at 1.903 GiB; that is not process-attributed. Per-arm clock samples spanned CPU 729.6–2,201.6 MHz, GPU 306–1,300.5 MHz and EMC 3,199 MHz. Clocks were observed, not controlled. Energy was not measured, and the raw system rail readings were not integrated. Timing, memory and clock observations are aligned by arm in `analysis.json`.

This result closes the held-out timing check for this exact staging candidate and workload. It does not quantify pinned staging on other prompt lengths, formats, or service profiles, and it does not close Phase 3's broader graph-backing and transfer gates. Raw per-arm logs remain ignored by Git; their hashes are retained in `SHA256SUMS.txt`.
