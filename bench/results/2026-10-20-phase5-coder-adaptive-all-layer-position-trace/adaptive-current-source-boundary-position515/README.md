# Current-source adaptive recovery boundary at position 515

This is a same-service short/long/short correctness diagnostic for the Coder
IQ1_M model on Orin1. It compares delayed adaptation with cap-8 adaptive swaps
using the current candidate binary. It is not a performance measurement or a
Phase 5 closeout.

The campaign passed both supervised arms. They used seed `2026102230`, the
`short-long-short` request sequence, 12 generated tokens per request, prompt
cache 6, configured speculation 2, and native CPU Q8_1 dot enabled for all
eligible rows. The model is
`ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-Coder-GGUF` IQ1_M at revision
`5348543e0147355ac9cbcb031184a3546350988e`. Both arms ran the same binary
SHA256 `081212f0e855640747b3d2595d8f8837df7d99a4eb778dc22b7bc7f2d6e76c9d`
and source tree HEAD `8e7400fdd91d53b5634aab0923c9bf0a8b7294a5`.

The two short requests emitted identical 12-token sequences in each arm, and
the delayed control returned to exactly the same accepted-state fingerprints
after the intervening long request. Adaptive recovery also reproduced the
short request's emitted tokens and PLE fingerprint, but its accepted state
differed in GDN, tail, pooled, pooled-full, and KV fingerprints. The layer-16
verifier boundary capture at position 515 makes the difference concrete:
delayed control reproduced all eight captured fields bitwise, while adaptive
recovery changed every value in `R`, `bo`, and `inj2` after layer 16 and before
the layer-17 read. It also changed all captured post-read `R` and `xn` values.

The layer-16 verifier inputs show that the discrepancy is already present
before the captured layer's experts run: all 2,560 input values differ between
adaptive initial and recovery (maximum absolute difference `0.02695364`,
relative L2 `0.01280480`). Expert IDs are unchanged, but router weights differ;
all 25,600 captured expert-output values and all 2,560 combined MoE-output
values differ. The delayed-control input, routes, weights, expert rows, and
combined output are bit-identical across recovery. This capture therefore
does not implicate an expert owner or isolate the earlier source of activation
drift; layer 16 receives an already changed activation and propagates it.

At the later boundary, initial short-request layer-17 pre/post-GDN state is
bit-identical between arms. Adaptive's recovery pre-GDN state remains
bit-identical to its initial request, but post-GDN state differs in 796,657 of
817,152 values (maximum absolute difference `0.05024695`, relative L2
`0.00442930`). Delayed-control pre/post states are bit-identical across
recovery. Taken together, the capture shows an adaptive history-dependent
activation difference by the layer-16 verifier input and a later changed
layer-17 GDN result. It does not establish where before layer 16 the drift
begins, identify its cause, or prove the behavior across other prompts.

Minimum host/admission availability was 14.09 GiB for delayed control and
14.31 GiB for adaptive, above the preserved 6-GiB host headroom; both
supervisors reported no cgroup memory events. See `campaign.json`, each arm's
`result/analysis.json` and supervisor telemetry, plus the boundary and GDN
summary JSON files. The GDN pre/post summary uses the documented `STGSTAT1`
capture layout and compares both halves of each record directly. Layer-16
expert output and combined-output summaries were generated by
`compare_layer25_verifier_parts.py` with layer 16 selected; verifier input
summaries were parsed with the phase's existing `STTMOINP1` reader.

Reproduction command:

```sh
python3 bench/results/2026-10-20-phase5-coder-adaptive-all-layer-position-trace/run_pair.py \
  --run --seed 2026102230 --continuations 0 --sequence short-long-short \
  --generated-tokens 12 --native-cpu-q8-1-dot all \
  --capture-verify-moe-layer 16 --verify-moe-positions 515 --verify-moe-input-layers same \
  --capture-verify-gdn-layer 17 --verify-gdn-positions 515 \
  --capture-verify-gdn-state-layer 17 --gdn-state-positions 515 \
  --capture-boundary-layer 16 --boundary-position 515 \
  --output bench/results/2026-10-20-phase5-coder-adaptive-all-layer-position-trace/adaptive-current-source-boundary-position515
```

No runtime source changes were made for this diagnostic. The captured data
supports further Phase 5 localization only; accepted-state recovery remains
unqualified and Phase 5 stays open.
