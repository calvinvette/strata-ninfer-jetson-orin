# Q2_0 actual 32K prompt admission — Orin — 2026-10-11

This extends the Q2_0 configured-context measurements with actual 32,768-token
prompt ingestion. It ran on local `orin1` (Orin AGX, ARM64, CUDA 12.6) using the
native Q2_0 shards, the matching PLE pack and expert profile, `--prefill 512`,
`--spec 2`, `--prompt-cache 6`, and a 32,800-token context reservation. One
output token was requested. The current candidate
binary and all model/pack/profile identities are in `artifact-identities.json`;
full arguments, prompt hash, output ID and usage are in
`attempt-3/workload.json`. The exact prompt was generated by the retained
`runner.py` and validated at 32,768 tokens before engine launch. Two runs used
the 256-slot cache and two used 3,000 slots; both profiles used the same prompt,
engine, context reservation and generation length.

The first two launches were rejected by Strata's request context validator
before prefill. Context reservations of 32,769 and 32,770 tokens were both too
small for the internal boundary accounting; these are test-setup validation
failures, not capacity or engine failures. Their logs and supervisor samples
are retained under `attempt-1/` and `attempt-2/` (including `engine.txt`). The 32,800-token attempt
passed validation and ingested all 32,768 tokens, as confirmed by both the
prompt trace and `prompt_read`. It emitted token ID 32. No prompt tokens were
reused. The configured reserve was sufficient for this one request.

Prompt processing took 187,923.9 ms and the one-token decode took 230.7 ms.
These are descriptive values from a single admission request, not a benchmark
or a quality comparison. Supervisor status was `pass`; minimum host
`MemAvailable` was 21,316,354,048 bytes (19.85 GiB), above the six-GiB floor.
Across 190 memory/clock samples, GPU rates ranged 306–1,300.5 MHz (median
1,122 MHz), EMC remained at 3,199 MHz, and sampled CPU rates ranged 729.6–2,201.6
MHz. Clocks were observed, not controlled. Energy was not measured; raw
tegrastats rails are retained.

The opt-in owner trace recorded 304 allocations and 303 frees. The session
requested peak was 992,360,448 bytes; prefill peaked at 350,079,744 bytes;
verifier at 45,837,056 bytes; pageable expert-stage host backing at 353,894,400
bytes; mapped verifier host staging at 495,480 bytes. Those owners returned to
zero requested live bytes. The 1,485,606,400-byte dense WeightTable arena
remained live at the end of the engine log, consistent with its process-lifetime
weight ownership; process termination is not represented as an owner free.
These are requested bytes at instrumented sites, not total physical use. Graph
pool/driver bytes and other uninstrumented allocations are not priced by this
trace. The six-GiB host `MemAvailable` measurement remains the physical-memory
authority; CUDA capacity is not added to host RAM.

All four primary admission/repeat requests passed the supervisor. Minimum host availability was
19.85/19.94 GiB in the 256-slot runs and 17.10/17.19 GiB in the 3,000-slot
runs. Requested expert-cache backing peaked at 353,894,400 bytes and
4,147,200,000 bytes respectively; the larger profile's concurrent instrumented
device-request peak was 7,021,083,648 bytes. These requested bytes do not add
to host capacity and do not measure physical backing. Startup host availability
and file-cache state differed between campaigns, so the deltas are not a paired
measurement of cache cost.
The additional GDN-dump and first-logit capture runs also passed, with minimum
availability of 20.65/20.12 GiB at 256 slots and 17.22/17.33 GiB at 3,000 slots.

Within each cache profile, both runs matched all ten persistent-state
fingerprints and all 36 GDN layer fingerprints exactly. Across profiles,
output IDs still matched, but GDN, KV, tail, pooled and pooled-full
fingerprints differed; 35 of 36 GDN layer fingerprints differed. PLE, MTP,
stale, dead and PLE-previous fields matched. This repeatable cross-profile
state mismatch is an unresolved correctness result, not state parity. It blocks
any claim that the two cache settings are semantically interchangeable; no
cause is assigned by this screen. The low-16-bit per-layer GDN digests printed
at the end of prefill matched across all four runs; these short digests do not
prove byte equality. Full FP32 GDN dumps from an additional run per cache
profile differed in 27,341,442 of 29,417,472 values (92.94%). Mean absolute
difference was 0.000802, RMS difference 0.006706, maximum absolute difference
0.91895, relative L1 2.42%, and relative L2 2.48%. Strata's source documents
that a resident GPU expert and a CPU-computed miss use different floating-point
accumulation order ([expert-cache path](../../../src/program/generate.cpp));
the observed hit counts also differed (2/480 versus 54/480). That is a
plausible explanation, not a demonstrated cause. First-window logits had the
same argmax (token 32) and all top-20 tokens in common, but differed by 0.1002
RMS and 0.572 maximum absolute logit; total variation distance was 0.01967 and
the symmetric KL values were 0.00111/0.00110. The probability assigned to token
32 was 0.6127 versus 0.5972. These cross-profile diagnostics have no independent
whole-model oracle or adopted tolerance, so they establish neither quality
parity nor a quality failure. Compressed first-window logits and full summary
statistics are in `numerical-diagnostic/` and `numerical-diagnostic.json`;
full state dumps remain outside Git. Per-run final fingerprints are compared in
`state-comparison.json`.

These runs establish admission for the tested 32K prompt and both cache
profiles, not 32K quality, concurrency, performance, a supported capacity
limit, or graph-pool size. Broader pressure and memory-attribution gates remain
open; no default changed.
Models and generated packs remain under `/home/calvin/models/` and are not in
Git. The current candidate passed `ple_parity` and `ple_reader_selftest` (2/2)
and Python integration unittest discovery (99/99) after these diagnostics.
