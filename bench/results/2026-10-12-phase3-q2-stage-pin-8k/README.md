# Q2_0 8K prompt: pageable versus pinned expert staging — Orin — 2026-10-12

This Phase 3 screen compared pageable and pinned host backing for the expert staging buffers on the same Q2_0 model, 8,192-token prompt, eight-token continuation, 3,000-slot cache and 8,232-token context. As required by the current harness, both arms used eight-worker asynchronous prefetch with host staging enabled; `STRATA_STAGE_PIN=0` and `=1` selected pageable and pinned host backing. The run used a 24-GiB systemd cap and the unchanged six-GiB headroom floor. Model files stayed under `~/models/`.

Two randomized pairs completed before the supervisor safely aborted pair 3 at 5.65 GiB effective headroom; minimum host availability remained 17.76 GiB and the scope recorded zero OOM/OOM-kill events. Both complete pairs matched token IDs and all persistent-state fingerprints. The pageable and pinned stage owners each requested 353,894,400 bytes (337.5 MiB), and owner events show those buffers freed after each request. Pinned-minus-pageable request-time deltas were −4.78% and +0.94%; their median was −1.92%, with only two pairs and no useful performance conclusion. Do not promote pinned staging from this partial screen.

The first attempt was rejected by harness validation because it requested fewer than the required eight output tokens. The next attempt exposed the exact-context boundary and made no request; the harness now reserves 32 tokens beyond prompt plus output (while retaining the 8,192 minimum), with a regression test. The corrected run then produced two complete pairs before the documented pressure abort. The [focused staging tests](../../../tools/integration/test_stage_buffer_parity.py) passed 9/9 and full integration Python discovery passed 120/120. The current-binary [Q2_0 PLE regression](../2026-10-12-phase3-q2-ple-current-rerun/README.md) passed all seven stages; focused CTest passed 15/15.
