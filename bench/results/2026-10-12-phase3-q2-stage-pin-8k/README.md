# Q2_0 8K prompt: pageable versus pinned expert staging — Orin — 2026-10-12

This Phase 3 screen compared pageable and pinned host backing for expert staging on the same Q2_0 model, 8,192-token prompt, eight-token continuation, 3,000-slot cache, and 8,232-token context. Both arms used eight-worker asynchronous prefetch with host staging enabled; `STRATA_STAGE_PIN=0` and `=1` selected pageable and pinned backing. The six-GiB headroom supervisor remained active in both campaigns. Model files stayed under `~/models/`.

The first campaign used a 24-GiB cgroup ceiling. Two randomized pairs completed with matching output IDs and persistent state, but the supervisor safely aborted pair 3 at 5.65 GiB effective headroom (17.76 GiB host availability, no OOM). The completed pairs had mixed request-time results: pinned staging was 4.78% faster in one pair and 0.94% slower in the other. These two pairs remain a separate partial result in `paired-summary.json`.

A fresh three-pair campaign raised only the cgroup ceiling to 28 GiB. All six requests passed, and each randomized pair matched output IDs and all recorded persistent-state fingerprints. Every arm confirmed 3,000 cache slots. Minimum host availability was 17.75 GiB and minimum effective cgroup headroom was 10.60 GiB; cgroup OOM and OOM-kill counters stayed zero. CPU clocks varied from 729.6 to 2,201.6 MHz, GPU from 306 to 1,300.5 MHz, and EMC readback stayed at 3,199 MHz; clocks were observed, not controlled.

Each arm requested 353,894,400 bytes (337.5 MiB) for its corresponding pageable or pinned stage buffers. The owner traces balanced 256 stage allocations and 256 frees per arm. Pinned-minus-pageable end-to-end request-time deltas were −4.80%, +46.16%, and +0.83%; the median was +0.83%, with the paired three-sample bootstrap percentile interval from −4.80% to +46.16%. Prompt and decode effects also have wide intervals. This is inconclusive, with a large second-pair reversal, so pinned staging is not promoted.

Two setup issues were preserved before the campaigns: the harness rejected a one-token output because it requires at least eight, then rejected exact prompt-plus-output context. No request ran in either attempt. The harness now reserves 32 tokens beyond prompt plus output (and keeps its 8,192 minimum), covered by a regression test. Focused staging tests passed 9/9; full integration Python discovery passed 120/120. The current-binary [Q2_0 PLE regression](../2026-10-12-phase3-q2-ple-current-rerun/README.md) passed all seven stages and the focused CTest selection passed 15/15.

`completed-28g-summary.json` contains the complete paired screen, telemetry scope and per-run log hashes. Machine results and supervisor telemetry for the full run, 24-GiB partial run, and setup failures are committed in their respective directories. `SHA256SUMS.txt` verifies committed artifacts; `ENGINE_LOG_SHA256.txt` identifies local engine logs that remain ignored by Git. This is one prompt/cache/context screen; no transfer mode or default changed and Phase 3 remains open.
