# Q2_0 PLE rerun and QFUSE owner smoke — Orin — 2026-10-10

The artifact-aware Q2_0 `ple_parity` oracle and the focused Phase 3 memory / ownership set were rerun under `tools/integration/run_control.py` with the ordinary 6 GiB availability floor. All 10 selected tests passed in 49.3 seconds: `vmm_test`, `native_dense_ple_key_test`, `expert_cache_segmented_test`, `ple_parity`, `expert_cache_memory_test`, `expert_cache_memory_refusal`, `platform_memory_test`, `pinned_fallback_test`, `pinned_shared_test`, and `ple_reader_selftest`. Minimum `MemAvailable` was 25,866,530,816 bytes (24.09 GiB). Raw supervisor data is in `result.json`, with CTest output in `stdout.txt` and system telemetry in `tegrastats.txt` and `memory.jsonl`.

An opt-in `STRATA_QFUSE=1` Q2_0 smoke then exercised serial requests and two concurrent batch slots. Both prompts generated the same one-token outputs as the default-route control, and the QFUSE run's serial and batched outputs and reported state fields matched by prompt. The owner trace recorded a 320-byte `verifier-aux-device` allocation and its free. Minimum availability was 16,648,577,024 bytes (15.51 GiB). These are short one-token checks, not a performance result.

A separate detailed run enabled per-layer GDN state fingerprints. The default route produced input-dependent GDN hashes. Under QFUSE every displayed per-layer GDN digest had low 16 bits `8383`, while the full GDN fingerprint was `2d2b4c71fb470383`; the default full fingerprints were input-dependent (`ae0a7328db34c541` and `a8db8013920dad15`). A rebuilt diagnostic now validates the session-size call and rejects zero-byte or non-divisible per-layer ranges. The QFUSE run passed that guard and reproduced the same full GDN fingerprint, confirming the range was non-empty; the repeated low-16-bit per-layer values are truncated hashes and do not prove the rows are empty or equal. Other state fields and sampled tokens matched, but the full GDN fingerprint differs from the default route, so GDN parity remains unverified. The failed comparison is preserved in `cross-mode-comparison.json`. QFUSE remains opt-in and unqualified on Orin until the GDN state difference is explained and direct state parity is captured.

The detailed default and QFUSE runs each completed their serial/batch checks under the six-GiB supervisor. The state-hash size guard was then rebuilt natively and rerun with QFUSE; it did not reject the valid session carve. The guard change is a diagnostic hardening only and does not resolve the cross-route fingerprint difference. Per-layer logs and raw telemetry are in `../2026-10-10-phase3-qfuse-detail-default-ok/` and `../2026-10-10-phase3-qfuse-detail-enabled/`. One earlier diagnostic attempt failed before engine launch because its temporary JSON config was malformed; the retained failure is in `../2026-10-10-phase3-qfuse-detail-default/` and is not a runtime failure.

After the diagnostic change, `ple_parity`, `ple_reader_selftest`, and `native_dense_ple_key_test` passed again under the memory supervisor; the raw rerun is in `../2026-10-10-phase3-ple-post-guard/`. The source build and backend evidence for the range guard are summarized in [its report](../2026-10-10-phase3-state-hash-guard/README.md).

This work does not close Phase 3: graph executable/driver memory remains unattributed on Orin, explicit release evidence for split-stage and batch session backing remains open, and transfer / admission work still lacks the full set of energy and physical-allocation measurements described in `docs/integration/BENCHMARKS.md`.
