# Q2_0 32K prompt: mapped reads versus asynchronous pread — Orin — 2026-10-12

This randomized Phase 3 screen compared bounded mapped expert reads with asynchronous `pread` for one exact 32,768-token prompt and eight generated tokens. It used the same Q2_0 model, engine binary, 3,000-slot expert cache, 32,808-token context reservation, eight pread workers, and disabled host staging in all arms. The prompt SHA-256 is `705dea47aafbfc991d0616621f3a13bf0136a43c546d60c7693c2efdced4d3a3`; model and pack identities are recorded in the [artifact identity record](../2026-10-11-phase3-q2-admission/artifact-identities.json). Models remained in `~/models/`.

All three randomized pairs completed under a 28-GiB systemd memory ceiling and the unchanged six-GiB admission floor. Every pair matched generated token IDs, actual cache slots, and all recorded persistent-state fingerprints. Minimum host availability was 17.16 GiB and minimum effective cgroup headroom was 8.34 GiB; the supervisor reported no OOM events. The capped process used dynamic clocks (CPU observed 363–3,199 MHz, EMC 3,199 MHz); GPU clock sampling was unsupported in the request sampler. Clock changes were not requested.

Request-time deltas, defined as `(pread / mapped - 1) × 100`, were +14.58%, −0.48%, and −0.001%. The median was −0.001%, with a paired three-pair bootstrap percentile interval of −0.48% to +14.58%. Pread's scoped cgroup read bytes were lower by 5.15, 5.40, and 2.86 decimal GB, respectively; major faults were lower by 250,700, 297,582, and 264,931. These scoped effects are strongly affected by page-cache carryover between arms: no cache flush was attempted, and both modes read the same files. They do not establish a cold-read advantage or a reliable end-to-end win. Request-local logs report roughly 321 GB of logical expert reads per arm, illustrating that the logical read counter is not physical storage traffic.

The result is an inconclusive single-prompt screen, not a promotion. It does not cover managed memory, explicit device/pinned copy, async-pool ownership alternatives, or different cache/context points. `paired-summary.json` contains per-pair values, state/output checks, telemetry, and local log hashes. `experiment-3pairs/` retains machine results and tegrastats samples; engine logs are ignored by Git and remain on Orin. `supervisor-3pairs/` retains memory, clock, and terminal records.

Regression checks after the screen passed: the [current Q2_0 PLE rerun](../2026-10-12-phase3-q2-ple-current-rerun/README.md) passed all seven numerical stages for three tokens; the focused memory/cache/PLE CTest selection passed 15/15 in 37.26 seconds; full integration Python discovery passed 119/119 in 6.60 seconds. These verify contracts and harness behavior, not transfer performance or Phase 3 completion.
