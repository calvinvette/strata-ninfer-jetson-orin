# IQ3_S current-candidate performance — Orin — 2026-10-24

This is a seven-block, single-candidate performance run of the current Strata
integration binary on the original Qwen3.8-Flash-Next IQ3_S model. It extends
the Q2_0 profile's runtime settings to IQ3_S; it does not qualify IQ3_S as a
release profile and is not a paired speedup comparison against Q2_0.

## Workload and profile

The model was loaded through the native GGUF path from both IQ3_S shards. The
IQ3_S pack was built under `~/models/strata-orin-validation/iq3-s-pack` using
the Q2_0 base pack only for byte-identical shared float tensors. Quantized
weights, the PLE key and PLE table came from the IQ3_S GGUF shards. Hugging Face
metadata pins both shards to revision `ed59f92082b1e93c0e96d60a8b11aab089b52f09`.

Each independent process used an 8K context, FP16 KV, MTP off, prefill chunk
128, eight CPU pool workers, a 3,000-slot expert-cache request, 3,072 MiB
workspace reserve, `--mmap-experts`, prompt cache off, and no adaptive swaps.
The runtime realized 3,904 expert slots (7.44 GiB) from the 3,000-slot request.
Each process sent one warmup and one measured request for each of the two
standard workload shapes, with workload order randomized between blocks. The
warmup is excluded from the table. All 14 measured requests used fresh prefill
and emitted the requested 64 or 128 tokens.

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 512 / 64 | 7 | 13.1 (12.7–13.2) | 5.7 (5.6–5.9) | 40.06 | 50.82 | 53.99 | 33.81 |
| 2,048 / 128 | 7 | 22.1 (21.5–22.2) | 6.3 (6.3–6.4) | 93.46 | 112.93 | 140.31 | 50.08 |

Rates are Strata's engine-reported prompt and generation rates. TTFT is client
time to the first nonempty streamed content; client request time covers the
whole streamed response. The maximum is the descriptive p95 estimate for seven
observations, not a stable tail-latency estimate. Intervals are 20,000
nonparametric bootstrap resamples of independent process blocks and describe
the median within this one-candidate campaign; they are not paired effects.

The first block's 2,048-token prompt was slower (17.0 tok/s) than later blocks;
it is retained. File-cache state was not cleared and evolved naturally between
blocks. The measured host NVMe read deltas were large, especially for the longer
workload. They are device-wide `/proc/diskstats` observations, not process or
model-file attribution; concurrent host I/O and kernel read-ahead are included.
Endpoint samples were within 0.50 seconds of the request boundaries.

## Memory, clocks and scope

The supervisor used a 28-GiB cgroup cap and a six-GiB minimum admission floor.
Minimum host `MemAvailable` was 12.77 GiB and minimum host/cgroup admission
availability was 10.07 GiB across startup and requests. The request-aligned
sampled host minimum was 12.77 GiB. The largest observed system swap use was
3.60 GiB (1.45 GiB before the campaign); cgroup low/high/max/OOM/kill event
counters stayed at zero. The runtime kept the workspace reserve separate from
the realized 7.44-GiB expert cache.

Orin was in MAXN with dynamic clocks: sampled CPU frequency ranged from 0.730 to
2.202 GHz and GPU frequency from 306 to 1,300.5 MHz. `tj` ranged from 48.75 to
61.0 °C. EMC clock readback was denied. No clocks were changed. Tegrastats
samples include named power rails, but this report does not attribute energy to
the process. The benchmark used the same IQ3_S prompt workload in seven fresh
server processes, not an accuracy oracle; each workload produced two distinct
output-text hashes across its seven repetitions. Output quality and exact
token-ID parity were not measured, so they are not qualified here.

This is not a direct Q2_0 versus IQ3_S speed comparison: the quantization
cohorts were not paired on the same day in this campaign. Do not use it to claim
a general IQ3_S speedup or to alter the bounded Q2_0 release profile.

## Reproduction

From the repository root on the Orin, after downloading the exact model revision
and preparing the IQ3_S pack described in `artifacts.json`:

```sh
systemd-run --user --scope --collect -p MemoryMax=28G -p IOAccounting=yes \
  python3 bench/results/2026-10-24-iq3s-current-candidate-performance/run_campaign.py \
  --blocks 7 --seed 2026102401 \
  --output bench/results/2026-10-24-iq3s-current-candidate-performance/reproduction

python3 bench/results/2026-10-24-iq3s-current-candidate-performance/summarize_campaign.py \
  --campaign bench/results/2026-10-24-iq3s-current-candidate-performance/reproduction \
  --output bench/results/2026-10-24-iq3s-current-candidate-performance/reproduction/summary.json
```

The checked-in result includes raw per-request server timings, one-second host
memory/disk/clock observations, tegrastats, and the exact campaign commands.
The original first shard and the downloaded second shard are both under the
user's model directory; neither model file nor generated pack is in Git.
