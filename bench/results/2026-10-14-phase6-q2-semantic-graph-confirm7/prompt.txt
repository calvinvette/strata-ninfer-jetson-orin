Service desk training case. A clerk enters the expression 17 x 19 in a desktop calculator, reads the result, and saves a report to a solid-state drive. The machine is running a graphical operating system and a spreadsheet application. The keyboard sends electrical transitions over USB; the application receives a character event only after the operating system handles the device report. The display is an output device, and the report must remain available after the application closes.

Workstation notes: The processor is a general-purpose CPU with registers, arithmetic logic, caches, and execution units. Main memory is volatile DRAM. The operating system, calculator, spreadsheet, document, and file buffers are all represented by data in memory while the user works. The CPU reads and writes memory through a controller. A memory address identifies a location; it does not by itself say whether the bytes represent a number, an instruction, or text. Applications interpret the same bit patterns according to their data types.

Event record: A key press first exists as a signal. The keyboard controller reports a scan code. A device driver and operating-system input path turn that report into a key event. The application receives the event, updates its input field, and shows the characters on screen. The spreadsheet parses the expression, represents operands and operators in binary, and requests a calculation. The CPU fetches instructions, decodes each instruction, and executes the required operations. Registers and cache hold values temporarily; RAM holds the program, input, intermediate values, and result. The display controller reads image data prepared for the screen.

When the clerk saves the report, the application converts its document representation into bytes and asks the operating system to write a file. The operating system may first copy those bytes into a file-system cache in RAM, then schedule a write to the drive. A successful save confirmation means the operating system accepted the request; durable storage follows the file-system and device write protocol. Later, opening the report reads bytes back from storage into memory before the application displays them.
