# Q2_0 captured graph backing at 8K configured context — Orin — 2026-10-13

Three fresh Q2_0 service processes sampled the Tegra NVMap IOVMM client table around the supported captured verifier path. Each used 3,000 expert-cache slots, speculation window 2, prefill 512, an 8,232-token configured context, and a 31-token API prompt followed by 24 generated tokens. The model files remained under `~/models/`. This is an 8K configured-context measurement; it is not an 8K prompt ingestion test.

All requests passed and emitted the same text and final persistent-state fingerprint. Each trace recorded three verifier graph instantiations and one commit-graph instantiation, with matching owner events. Each owner ledger counted 304 allocations and 303 frees, leaving only the 1,485,606,400-byte service-lifetime weight arena. The 28-GiB scopes passed the six-GiB supervisor; minimum host availability was 17.83, 17.86, and 17.88 GiB, with no scope OOM events. CPU clocks varied from 729.6 to 2,201.6 MHz, GPU from 306 to 1,300.5 MHz, and EMC readback was 3,199 MHz. Clocks were observed, not controlled; energy was not measured.

In all three runs, the NVMap process-owner counter was 9,139,712,000 bytes immediately before the first successful graph event and 9,211,695,104 bytes after the fourth, a repeatable interval increase of 71,983,104 bytes. This matches the interval measured in the separate 32K/spec2 Q2_0 request with a 5,000-slot cache. The interval includes adjacent synchronous device allocations; it is not isolated graph executable cost, graph-pool accounting, or total physical memory. The graph-disabled control remains unsupported for this native route, so no differential or default change follows.

The first run reused a probe script whose metadata was hardcoded for its old spec4/64K configuration. The retained service config and `/health` response establish spec2 and context 8,232; the result metadata was corrected while preserving the original values, and the probe now reads those fields from its config. `analyze.py` reconciles graph event timestamps, NVMap samples, owner summaries and supervisor records; it verified identical final state, four graph events, matching run status, and the exact interval in all three runs. Raw NVMap, owner and supervisor telemetry plus per-run configurations are committed; engine logs remain ignored by Git, with their hashes in `analysis.json`.
